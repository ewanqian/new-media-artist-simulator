# 引擎理论：为什么这个项目不只是 React 游戏壳子

《新媒体时间模拟器》的引擎不是单纯技术栈，而是一套围绕“新媒体艺术生态如何被体验、被拆解、被模块化”的方法。

## 1. 核心目标

让玩家不是“读到”艺术生态，而是“被它调度”。

也就是说：

- 预算会影响创作语气
- 场域会影响技能掉落
- 人际会影响研发方向
- 焦虑不是背景设定，而是系统资源
- 旧缓存、旧项目、失败经验都可被再利用

## 2. 受 Agent Skills 启发的技能观

这里的 skill 不是传统 RPG 里的固定职业技能，而更像：

- 方法模块
- 工作流插件
- 人格策略
- 场域过滤器
- 知识芯片

它们的作用，不仅是加数值，而是帮助系统回答：

- 你如何理解一个项目
- 你如何处理一个场域
- 你如何从失败中回收价值
- 你如何把经验显性化并传递给下一轮开发

## 3. 芯片地物 / 插槽系统

你提到的“芯片地物机架模拟器”在这个版本里被初步转译为：

- 干员外壳 = 主体框架
- 技能插槽 = 方法与工具的安装位置
- 地图 = 场域环境
- 研发队列 = 时间性的生产机制
- 库存奖励 = 未来可再调用的资源

换句话说，玩家不是在升级一个人，而是在逐步搭建一个“可运行的方法系统”。

## 4. 游戏不是目的，体验结构才是

这个项目表面是网页游戏，实际上更接近：

- 艺术生态模拟器
- 方法论可视化工具
- 叙事实验容器
- 个人创作引擎雏形

它要服务的不只是娱乐，而是：

- 自我分析
- 团队沟通
- 项目预演
- 方法论沉淀
- 对外展示一种新型艺术实践框架
