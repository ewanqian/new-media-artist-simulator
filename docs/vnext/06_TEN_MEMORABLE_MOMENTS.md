# v0.3 玩家旅程压力测试：10 个必须记得住的瞬间

这不是“再加十个事件”。这十个瞬间用来反推 Core Engine 是否真的够用。任何一个瞬间如果只能靠 UI 临时特判实现，说明底层协议还没定好。

## 总体节奏

- 1 Run = 20 Turns
- 1 Phase = 5 Turns
- 短时体验：1–5 Turns / 3–15 分钟
- 完整体验：20 Turns / 30–60 分钟
- 10 个记忆点不要求每局全部出现；首轮测试使用固定 Seed 跑一条“黄金路径”验证系统。

---

## 01. 你继承了一件不该成为装备的装备

**场景**：开局档案里出现「祖传 HDMI 转接头」。它磨损严重，却有 `reliable-under-pressure` 标签。

**有趣点**：看起来是垃圾，但后来可能在黑盒现场救命。

**引擎要求**：
- 资产模板 / 资产实例分离
- 唯一 instanceId
- durability / tags / persistence
- 装备槽 `tool` / `wildcard`
- 同模板不同实例可以拥有不同历史

---

## 02. 同一件事，被三个世界同时解释

**场景**：作品在开幕现场掉帧 12 秒。

玩家看到三个按钮式视角：
- **官方口径**：实时渲染系统在高并发状态下出现短暂波动。
- **无脑吹**：作品主动拒绝稳定帧率，成功暴露数字基础设施的脆弱性。
- **黑色幽默**：显卡替你完成了媒介批判。

**有趣点**：不是告诉玩家“正确解释”，而是允许三种话语同时存在。

**引擎要求**：
- Event 的 `lenses` 数据结构
- 预生成媒体附件
- 事件可以生成「证据资产 / 媒体卡」进入档案
- 分享不消耗 Turn

---

## 03. 你被一个阵营喜欢，也被它提防

**场景**：「学院新媒介委员会」邀请你加入，但你之前公开吐槽过它的评审机制。

结果不是单一好感度：
- Fame +8
- Infamy +6
- Membership = affiliate

**有趣点**：你变成“他们愿意邀请、但绝不放心”的人。

**引擎要求**：
- Fame / Infamy 双轴声望
- Membership 与 Reputation 分离
- 阵营特权、义务、敌对状态以后可扩展

---

## 04. 一个失败项目被你拆成了新装备

**场景**：大型空间装置预算崩溃。

玩家不只能“成功/失败”，还可以：
- 缩小项目继续做
- 把失败声明为方法
- 拆除项目并回收「铝型材骨架」「坏掉的追踪器」「失败文档」

**有趣点**：失败真的改变你的背包和未来，而不是一句文案。

**引擎要求**：
- Project 状态机
- project → asset salvage
- `repurposed / abandoned / archived` 等终态
- 连锁事件

---

## 05. 配装第一次让你发现“规则可以被组合”

**场景**：你同时装备：
- 方法：失败作为方法
- 工具：祖传 HDMI 转接头
- 生存：预算招魂术
- 载具：借来的折叠货运车

在「临时黑盒展演」事件里解锁隐藏选项：
> 「把灾难做成一个能开的版本。」

**有趣点**：不是 +5 技术，而是出现以前根本没有的行动。

**引擎要求**：
- loadout selectors
- 条件查询 tags
- 条件解锁 choice
- 不允许在事件代码里硬编码具体资产 ID，只查标签/能力

---

## 06. 你突然真的拥有了一个机构

**场景**：一个废弃 28㎡ 小空间可以接手。玩家成立「临时艺术基础设施办公室」。

小面板开始出现：
- 现金流
- 空间稳定度
- 声誉
- 设备
- 当前计划
- 合作者

**有趣点**：游戏突然从“我是艺术家”切成“我为什么开始维护消防、路由器和厕所”。

**引擎要求**：
- Institution 是一等实体，不是 UI 小游戏
- 机构资产可以引用玩家资产
- institution metrics 通过统一 Effect 修改
- Panel 只是机构状态的一个视图

---

## 07. 一张小红书式帖子把事情完全带偏

**场景**：系统生成一张预制的社交媒体卡：
> 「上海 28㎡ 神秘艺术空间｜进去以后 Wi‑Fi 比作品更互动」

突然：
- 可见度上涨
- 学术阵营 Infamy 上涨
- 商业合作机会增加
- 下一个 Event Pool 被改变

**有趣点**：传播不是单纯 reputation +3，而是重写后续概率。

**引擎要求**：
- MediaCard 作为可收藏资产
- world flags / conditions
- 事件池权重受状态影响
- 分享输出与游戏状态分离：分享动作不直接相信客户端“发成功了”

---

## 08. 你丢过一次数据，所以这个硬盘变成了角色

**场景**：旧 SSD 在一次事故后被抢救回来，从普通资产变成：
- `scarred`
- `recovered`
- `archive-anchor`

以后它会出现在文案、事件条件和结局里。

**有趣点**：物品开始有传记。

**引擎要求**：
- asset history / tags
- 资产长期 persistence = profile
- save migration 不能丢 instanceId
- 资产不是每局重置的数字计数器

---

## 09. 载具 / 机甲第一次不是“皮肤”

**场景**：解锁「展演后勤机甲 Mk.I」——本质上是一台荒谬的模块化运输/搭建平台。

它可以装：
- 电源模块
- 投影模块
- 路由模块
- 折叠屏幕

它改变旅行、搭建、机构运营的选择，但没有单独发明一套 RPG 战斗系统。

**有趣点**：非常荒诞，但仍然服务原作品主题：新媒体艺术家最后变成了移动基础设施维护工。

**引擎要求**：
- vehicle 仍是 Asset
- nested slots / attachment tags 后续可加
- 同一 Effect / Inventory / Persistence 体系

---

## 10. 结局不是“你赢了”，而是一份真的能留下来的档案

**场景**：Turn 20 结束，游戏生成一张阶段档案：
- 你加入/得罪了谁
- 哪个失败后来变成了工具
- 哪件资产活过了整个周期
- 你运营了什么机构
- 最荒谬的一次传播
- 三个互相矛盾的艺术家身份标签

并解锁一个跨 Run 的 Meta Title，例如：
> **「制度欢迎的麻烦制造者」**

**有趣点**：玩家得到的是一段“我这一局到底发生了什么”的可讲述故事。

**引擎要求**：
- History log 可重放
- deterministic seed
- meta persistence
- share/export renderer 只读状态，不修改核心状态

---

# 由这 10 个瞬间冻结的底层原则

1. **少量 Primitive，相互组合**：Event / Asset / Project / Faction / Institution / Media 不各自发明一套规则。
2. **内容是数据，规则是代码**：事件包、图片、台词、阵营可以频繁更新；Effect 协议谨慎更新。
3. **任何可持久化对象都有稳定 ID**。
4. **所有改变 GameState 的行为必须经过 Command → Validate → Effect → History**。
5. **随机必须可复现**，同 seed + 同 command history 得到相同结果。
6. **手机与桌面只换布局，不换规则**。
7. **媒体内容不塞进 Save**：Save 只保存 asset/media template ID 与状态，图片音视频由内容包提供。
8. **远程 Content Pack 默认只允许数据，不允许运行任意 JS**。
9. **多人以后把同一 Command 发给 authoritative server；单机不重写玩法。**
10. **Steam 以后只实现 PlatformAdapter，不进入 Core。**
