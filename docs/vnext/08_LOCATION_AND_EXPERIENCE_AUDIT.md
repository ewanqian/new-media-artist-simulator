# 新媒体艺术家模拟器：地点系统与体验审计

> 本文不是新的视觉提案。它用于解释为什么当前 v0.5 线框要继续改信息架构，而不是继续换皮。

## 1. 历代体验结构

### A. 巴别瓶 v0.3.1：四列卡片

主操作区同时出现四列：

1. 研究场域
2. 专业准备
3. 项目研究
4. 筹措经费

右侧是八维状态、成就时间线和艺术家档案。

优点：
- 一眼能看到“研究 / 准备 / 项目 / 生存”四类行为之间的竞争。
- 卡片量大，内容扩展成本低。
- 研究场域本身就有 13 个模板，内容密度高。

问题：
- “研究场域”其实是行动卡，不是真正的空间。
- 地点之间没有距离、父子关系、邻接、进入/离开、场地状态。
- 点击地点主要得到属性增减，空间不会记住发生过什么。
- 四列在内容变多后会产生强烈滚动和认知负担。

### B. React 重构版：6 区域 / 12 子地点

数据层把地点整理为 6 个区域，每个区域 2 个子地点：

- 榕树湾工作区
  - 共享工位 B-201
  - 江边大排档
- 深港加速走廊
  - 提案会议室
  - 黑盒测试场
- 南岭学院与展厅群
  - 理论讲堂
  - 学院展厅
- 离线渲染农场
  - 算力机架
  - 预演代理站
- 北方双年展工地
  - 旧机库展场
  - 媒体接待区
- 海外驻留港
  - 驻留实验室
  - 边界咖啡馆

优点：
- 第一次出现 Region → Submap 层级。
- 场域开始影响 action / NPC / skill 掉落。

问题：
- 每个区域固定两个子地点，空间仍然只是 action selector。
- 区域之间没有真正可读的相对关系。
- Dashboard 同屏放地图、方法网络、项目、库存、状态、日志，所有系统互相争夺注意力。

### C. v0.4：Attention 文本流

优点：
- 注意力作为核心资源成立。
- 文字决策节奏明显比 Dashboard 更轻。
- 历史和延迟回调开始成为玩法。

问题：
- 为了降低 UI 负担，把空间世界几乎全部抹平。
- 玩家只能纵向读事件，缺少“我在哪里 / 我还能去哪”的第三维。

### D. v0.5 World Hub：恢复地图，但混淆语义

恢复 x / y / adjacency 后，地图重新出现空间感；同时却把以下内容全部画成地图节点：

- 咖啡馆
- 工作台
- 场地预演
- 设备交换
- 档案
- 真实区域
- 离线渲染农场

这是当前最大问题：

**系统工具、专业服务、真实地点被放进了同一种空间语法。**

工作台和档案应该“随时可访问”；黑盒、展厅和驻留实验室才是“要去的地方”；远程算力更接近按需服务，不应该强迫每位艺术家在世界地图上拥有一块“渲染农场领地”。

## 2. 地点内容库存

当前仓库不是缺地点，而是缺分类。

### 早期内容
- 13 个研究场域模板。
- 数据驱动，可继续新增 JSON。
- 包含现象学实验空间、媒体考古实验室、认知科学艺术空间、人类世研究空间、后互联网研究所、系统美学实验室、批判性编程空间、具身认知实验室等。

这些名称多数更适合作为：
- 机构内部实验室
- 驻留项目设施
- 临时活动空间
- 特殊事件生成模板
- 世界内容包生成的地点实例

而不是永远固定在总地图上。

### React 地图内容
- 6 个区域
- 12 个子地点

### v0.5 已扩展的设施语义
在原有区域基础上，已经自然长出了第三类设施（后门装卸区、制作后场、征集办公室、制作办公室、项目房间等）。

修正后的线框保留其中：
- 5 个世界级区域节点
- 15 个区域内部设施
- 3 个专业技术服务
- 13 个旧研究空间模板

“离线渲染农场”的 3 项内容不删除，而从世界地图迁到专业服务层。

## 3. 新地点模型

地点应该允许无限扩充，但不要求所有地点都出现在同一层地图。

推荐层级：

`世界 / 城市 → 区域 → 地点 → 房间 / 设施 → 当前场景`

例如：

`深港加速走廊 → 黑盒测试场 → 主投影区 → 场地预演`

另有非空间层：

`全局系统 → 项目 / 工作台 / 关系 / 档案`

以及专业服务层：

`工作台 → 技术资源 → 远程算力 / 离线预演 / 数据恢复`

专业服务由项目和技能需要触发，不需要成为地图地点。

## 4. 相对位置应该表达什么

当前 x / y 不应被理解成真实 GPS。

它首先表达：
- 玩家对世界的认知地图
- 通勤 / 移动成本
- 机构与商业生态的相对聚集
- 哪些地点之间容易产生连续事件

后续渲染可以替换：
- 线框 2D
- 城市平面图
- 概念地图
- 动态背景
- 3D / Gaussian / WebGL 场景

但稳定 ID、parentId、adjacency 与访问条件不变。

## 5. 下一版线框的信息架构

### 固定系统层
左侧固定：
- 世界
- 项目
- 工作台
- 关系
- 档案

这些不占据地图坐标。

### 世界层
地图只放真实区域：
- 榕树湾工作区
- 深港加速走廊
- 南岭学院与展厅群
- 北方双年展工地
- 海外驻留港

点击区域进入区域内部设施。

### 地点内部
地点不是三张 action 卡，而是一组可以持续扩充的设施。

设施可以承载：
- 文本事件
- NPC / 关系
- 项目机会
- 场地预演
- 商业沟通
- 申请
- 展览安装
- 记录 / 档案回调

同一个设施以后可以换成 2D / 3D 背景，不改变其系统身份。

### 工作台
工作台只负责：
- 当前项目
- 制作条件
- 技能 / 方法
- 项目真正需要的专业服务

例如研究 / 批评路线默认不显示远程算力服务；影像、空间、实时系统路线在需要时才显示。

## 6. 当前体验评价

现有线框的视觉方向可继续使用，主要问题不是美术：

1. **语义层级错误**：工具和地点同权。
2. **地图信息密度错误**：地图节点数量看似多，但世界实际只有一个层级。
3. **上下文缺失**：进入地点后没有清楚显示“这里和谁、什么项目、哪些机会有关”。
4. **通用功能占据空间**：工作台、档案、设备交换不应占地图面积。
5. **专业偏见**：离线渲染农场把系统/图形路线默认成所有艺术家的共同世界。
6. **旧内容没有被真正继承**：13 个研究场域应该成为地点模板，而不是被新版地图直接覆盖。

下一轮优先级不是新增美术或更多项目，而是验证：

**全局系统与空间世界分离后，玩家是否第一次能明确感觉到“我有一套工作系统，同时我生活在一个可以不断扩张的世界里”。**
