# 新媒体艺术家模拟器 vNext：系统玩法基础

> 工作分支：`vnext/systemic-gameplay-foundation`
> 目标：在不推翻现有网页模拟器的前提下，把内容堆积升级为可组合、可持续扩展、可测试的游戏系统。

## 0. 版本定位

暂定版本名：**v0.3 Systemic Satire / 系统讽刺版**。

这不是重做，也不是把项目扩成大型开放世界。当前版本继续保持：

- 浏览器点开即玩；
- GitHub Pages 可直接部署；
- 单人、本地存档优先；
- 一轮 20 个工作单位；
- 场域、方法网络、在制项目、预算/档案/关系等现有骨架继续使用；
- 黑色幽默、多视角文本和艺术生态观察仍是作品核心。

vNext 解决的问题不是“再加 100 个 NPC”，而是：**已有内容是否真的互相作用，玩家是否能形成自己的玩法。**

---

## 1. 当前版本的真实问题

现有主线已经具备一轮完整创作周期，但系统之间的耦合仍然偏弱：

1. 行动大多仍是“点按钮 → 数值变化 → 日志一句话”。
2. 项目数量已经很多，但大部分项目的差异主要存在于名称、成本和奖励。
3. 库存物已经存在，但多数物品还没有产生明确的使用、装备、交换、事件解锁或阵营影响。
4. `emergency.js` 已经设计了很多有价值的补救行为，但尚未进入当前主循环。
5. NPC 的文本有气质，但人物更多承担随机台词触发器，而不是系统接口。
6. 特殊事件的三层文本结构已经在设定层成立，但尚未真正成为核心玩法对象。
7. “地图、方法节点、项目、库存、关系人物”目前更像并列栏目，而不是互相发生化学反应的对象。

因此 vNext 的首要任务是：**减少孤岛系统，增加乘法关系。**

---

## 2. 六条不可破坏的设计原则

### P1. 点击必须是一个“动词”

网页点击不是菜单导航，而是玩家行为：

- 接受 / 拒绝
- 借 / 卖 / 装备 / 拆解
- 加入 / 背叛 / 保持模糊关系
- 公开 / 隐藏 / 包装 / 反讽
- 投资 / 缩编 / 外包 / 通宵
- 把失败变成作品

每个新面板都必须至少提供一个新的动词，否则只是信息展示。

### P2. 规则优先于内容数量

不追求“事件 500 条、NPC 200 个”。

先建立少量一致规则，让不同内容互相作用。例如：

- `unstable` 不稳定
- `portable` 可移动
- `institutional` 制度性
- `viral` 易传播
- `open_source` 开源
- `expensive` 高成本
- `deprecated` 过时
- `ai_generated` AI 生成
- `site_specific` 场地特定
- `public` 公开

规则在所有系统里都应保持相同含义。

### P3. 事件不是弹窗，而是“状态变异器”

一个好事件发生后，至少留下一个长期结果：

- 一件资产；
- 一个身份标签；
- 一段阵营关系变化；
- 一个后续事件入口；
- 一张媒体记录；
- 一个机构状态变化；
- 一个新的面板或行为。

如果事件关闭以后什么都没留下，它只是段子，不是玩法。

### P4. 每个资产都必须有 affordance

资产不只是收藏品。每个资产至少应该能：

- 装备；
- 消耗；
- 交换；
- 拆解；
- 改造；
- 触发事件；
- 改变某个场域行为；
- 改变别人怎么看你。

### P5. 同一件事允许三个同时成立的视角

vNext 固定保留三视角文本：

1. **官方 / 中性记录**：事情实际上发生了什么。
2. **吹捧 / 宣传口径**：这件事如何被包装成“重大进展”。
3. **黑色幽默 / 讽刺口径**：它荒谬在哪里。

三者不负责告诉玩家哪个才是真相；它们共同构成作品。

### P6. 玩家信任高于随机惊喜

所有系统必须具备可解释性：

- 同类标签在不同地方遵守同一规则；
- 随机数可复现；
- 事件不会让存档进入非法状态；
- 旧存档可以迁移；
- 关键变化可追溯；
- 玩家能够理解“为什么发生”。

## 3. 新的核心循环

### 3.1 30 秒微循环

`看状态 → 做一个动作 → 出现结果/事件 → 留下一点东西`

适合第一次点进网页的人。

### 3.2 5–15 分钟短循环

`进入一个场域 → 做 3–5 个动作 → 遇到一个特殊事件 → 调整配装/关系/项目 → 生成阶段卡片`

这应该成为小红书、聊天转发和朋友试玩时最自然的体验长度。

### 3.3 30–60 分钟完整循环

继续沿用当前 20 个工作单位：

`选实践谱系 → 建立方法配装 → 移动场域 → 接项目/做研究/维持生存 → 事件连锁 → 阵营与资产变化 → 本轮归档`

### 3.4 长期循环

多轮游戏以后保留：

- 玩家档案；
- 解锁资产图鉴；
- 特殊身份；
- 阵营历史；
- 机构经营记录；
- 媒体档案；
- 稀有事件记录；
- 可分享的“艺术家生涯年鉴”。

长期循环不能让老玩家数值碾压新玩家，优先积累**选择权、奇怪资产、故事和身份**。

## 4. vNext 九个系统对象

### 4.1 Player / 玩家档案

保存基础身份、实践谱系、状态、标签、历史。

### 4.2 Loadout / 配装

从现有“方法网络”自然升级：

- 方法论槽；
- 工具槽；
- 社交接口槽；
- 生存手段槽；
- 偏门手段槽；
- 后续可增加载具 / 移动工作站 / 机器人 / 机甲等荒诞资产槽。

重点不是“战斗力”，而是改变你能怎么处理问题。

### 4.3 Asset / 资产

统一承载：设备、文件、许可证、媒体报道、交通工具、工作室设施、奇怪机器、名片、人情、奖项、债务等。

### 4.4 Project / 项目

项目从“倒计时奖励”升级为可被事件改变状态的对象：

`idea → proposal → production → blocked → patched → shown → archived`

项目可以失败、缩水、换名、延期、被收购、被误读、被二次利用。

### 4.5 Event / 事件

核心内容系统。事件可以读写其他所有对象。

### 4.6 Faction / 阵营

艺术学院、商业品牌、独立空间、技术社群、收藏市场、公共机构、网络社区等，不直接映射真实机构。

阵营关系不只是一根好感度。

### 4.7 Institution / 机构

允许玩家在中后期“运营一个东西”：

- 工作室；
- 独立空间；
- 小型厂牌；
- 研究小组；
- 临时展览机构；
- 线上频道。

机构本身也是资产组合器。

### 4.8 Media / 媒体档案

预生成图片、短视频、海报、假新闻截图、聊天记录、邀请函、表格、奖状、报错界面都可以成为事件媒介。

### 4.9 Record / 游玩记录

所有关键决策写入事件日志，未来用于：

- 存档；
- 生成结局；
- 分享卡；
- 多人同步；
- 重放；
- 自动测试。

---

## 5. “艺术圈化学系统”

不复制《塞尔达》的火水电，而是建立适合本作品的状态规则。

### 5.1 条件（Conditions）

例如：

- 预算紧张
- 舆论过热
- 技术不稳定
- 截止日期临近
- 机构认可
- 网络爆红
- 场地受限
- 作者身份模糊
- 作品不可维护

### 5.2 特质（Traits）

项目、资产、机构、人物、事件都可拥有统一标签。

### 5.3 组合示例

**开源工具 + 商业项目**

→ 可以降低成本；
→ 也可能触发“授权到底算谁的”事件。

**AI 生成 + 学术场域**

→ 可能增加议题热度；
→ 同时增加作者性争议。

**大型空间 + 低预算**

→ 自动提高“临时拼装”事件权重；
→ 如果玩家有 `portable` / `salvage` 资产，则产生不同解法。

**爆红媒体资产 + 独立空间阵营**

→ 名声上升；
→ 也可能被认为“太会营销”。

同一规则在任何事件中都遵守相同逻辑，玩家才能学会利用系统。

---

## 6. NPC 的新定位

NPC 数量不是 KPI。

vNext 中 NPC 只在以下情况下存在：

1. 代表一个制度接口；
2. 提供一个独特玩法；
3. 持有某类资产或权限；
4. 能改变事件处理方式；
5. 与玩家形成持续关系。

如果一个 NPC 只提供三句随机台词，不应优先新增。

---

## 7. UI 原则：面板就是玩具

未来界面允许越来越多“小插件式面板”，但每个面板都是可操作系统：

- 特殊事件面板
- 资产箱
- 阵营关系图
- 项目工作台
- 机构运营台
- 媒体流
- 个人档案
- 数字钱包
- 身份凭证
- 载具 / 移动工作站面板
- 装备 / 方法配装
- 拍卖 / 展览 / 驻留子模拟器

UI 可以越来越丰富，但核心状态只有一份，避免每个面板自己维护一套逻辑。

---

## 8. 明确不做

v0.3 暂时不做：

- AI 自主生成全世界剧情；
- 大量自主 NPC；
- 强制联网；
- 区块链资产化；
- 实时 MMO；
- 复杂 3D 地图；
- 为了“先进”重写全部现有 UI。

这些都可以以后成为显示层或适配器，但不能先污染核心玩法。
