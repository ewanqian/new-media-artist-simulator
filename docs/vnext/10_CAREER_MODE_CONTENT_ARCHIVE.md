# v0.6 生涯模式：资源归档与内容生产框架

> 目标：停止继续扩顶层系统，把现有引擎、文本、节点、地点、人物、事件和档案全部转入“填内容 / 打磨体验”的生产阶段。

## 0. 这次冻结什么

玩家正面只需要两个模式：

1. **生涯模式 / CAREER**：角色建模 → 新手引导 → 五阶段职业生涯 → 长线任务 / Episode / 特殊事件 → 阶段档案。
2. **自由创作 / FREE CREATE**：节点画布。新建空白、打开最近蓝图、保存、另存、导入、导出、分享都属于这一模式。

不再把“节点编辑器”当第三种游戏模式。节点编辑器是：
- 自由创作的主要界面；
- 生涯模式里的可选工作方法；
- 某些项目 / Episode 的深度交互界面。

系统工具单独放：
- 内容管理
- 导入 / 导出
- 设置

`FIELD / WORKBENCH / RECORDS` 继续是生涯模式内部唯一三层结构，不增加第四层。

## 2. 生涯模式五阶段

五阶段是**长期节奏**，不是五个菜单。

### STAGE 1 — 起点：第一个能被别人看见的版本

**核心问题**：你到底做什么？别人能不能看到一个真实存在的版本？

玩家第一次学会：
- 从自己的桌面开始
- 做一个最小系统 / 整理材料 / 媒体考古
- 第一次把版本发给别人
- 第一次进入真实环境
- 第一次出现故障
- 第一次公开

强主线：**《第一个能被别人看见的版本》**

结尾不是“升级”，而是生成第一份阶段档案：
- 第一个项目是什么
- 第一个见证人是谁
- 第一次失败是什么
- 哪个方法因此被记录

### STAGE 2 — 现场：世界会反击

**核心问题**：桌面上成立的东西，为什么到现场就不成立？

内容重点：
- 两小时测试档期
- 屏幕 / 投影 / 电力 / 信号 / 网络 / 声音 / 灯光
- 搭建窗口
- 真实尺寸
- 运输和撤场
- 备份与降级

这一阶段 Blueprint 开始真正有用，但仍可跳过。纯叙事玩家通过“选择制作方案”完成同一逻辑。

### STAGE 3 — 网络：别人开始因为一件事找你

**核心问题**：当项目开始进入关系网络，你怎么处理机会、责任和误读？

内容重点：
- 小委托
- Open Call
- 同行介绍
- 策展 / 制作 / 客户
- 一页项目版本
- Scope 变化
- 传播误读
- 第一次被“因为某件具体的事”记住

重点不是声望条，而是：**谁因为什么认识你、他们看过哪个版本、你欠了谁什么。**

### STAGE 4 — 方法：你不再每次从零开始

**核心问题**：哪些失败、工具、习惯和关系已经变成你的方法？

内容重点：
- 失败项目回收
- Blueprint 谱系 / Remix
- 方法节点
- 档案收藏组
- 教别人 / 工作坊
- 把旧项目拆成新项目
- 形成自己的生产方式

这一阶段开始出现“同一个问题，你已经有三种不同解法”。

### STAGE 5 — 基础设施：你开始维护一套自己的世界

**核心问题**：当你不只是在做作品，而是在维护空间、团队、系统、观众和档案，你还是什么？

内容重点：
- 接手一个很小的空间 / 临时基础设施
- 形成长期团队
- 设备、档案和方法跨项目复用
- 发起公开计划
- 维护一套长期项目
- 选择继续作为个人、团队、机构、游牧实践或混合状态

结尾生成一份真正能留下来的 **Career Archive**，而不是“YOU WIN”。

## 3. 三种游玩方式，同一套世界规则

这三种是 UI / 操作偏好，不是职业。

### STORY — 纯叙事

玩家不进入节点画布。
- 系统给 2–3 个具体制作方案
- 方案背后仍然使用相同 Environment × Capability × Project State 规则
- Blueprint 在后台生成 / 更新

适合只想体验剧情、人物和决策的玩家。

### HYBRID — 混合（默认）

大部分时间是生涯 / 文本 / 场域 / 对话。
只有在关键制作节点，系统问：
- “直接采用推荐方案”
- “打开工作图自己改”

### BLUEPRINT — 工作图优先

关键项目默认打开节点图。
适合喜欢系统、空间、技术生产链的玩家。

三种方式必须能进入同一主线、触发同一事件、得到同一种档案对象。

## 4. 角色建模：不是选职业，是决定“你从哪里开始”

开局角色由四部分组成：

1. **已有资源**：你现在手上有什么？
2. **熟悉动作**：别人通常因为什么找你？
3. **进入世界的关系**：你已经认识谁？
4. **操作偏好**：Story / Hybrid / Blueprint

问卷只生成隐藏的 Practice Signals，例如：
- systems
- spatial
- media
- research
- production
- social

这些标签只用于：
- 推荐开局资源包
- 推荐第一个项目种子
- 调整早期对话
- 调整事件池权重
- 提供一个“起始描述”

**不生成固定 Class，不锁技能树。**

玩家还可以跳过问卷，直接选择预置开局档案。

## 5. 强主线 NPC：让他们跨阶段存在

优先继续使用已经存在的人物种子，不扩散假 NPC。

### 林 / 同行艺术家
- STAGE 1：第一个真正看当前版本的人
- STAGE 3：介绍机会，也会指出玩家越来越像“只在交付”或“只在研究”
- STAGE 4：可能参与一次共同 Remix

### 李技术 / 现场技术
- STAGE 2 核心人物
- 永远先问分辨率、刷新率、接口、备份
- 玩家如果反复不记录技术信息，他会减少主动帮助
- 不是好感度，是对你“信息是否可靠”的判断

### M / 记录者
- 从第一阶段就提醒：不要只拍最终效果
- 后期会让失败文档、安装照片、版本差异真正进入 Archive

### 乔 / 制作人
- Scope、报价、客户、边界
- 商业内容不是道德分支，而是责任和资源分配问题

### 陈 / 场地 / 机构
- 第一次要求玩家把项目压成一页
- 后期可能给出机构机会，同时附带复杂条件

### 戴 / 制作与物流
- 尺寸、重量、运输、安装
- 玩家越早把这些信息说清楚，后续可用制作选项越多

人物关系记录：
`如何认识 → 一起做过什么 → 他看过什么 → 你答应过什么 → 他认为你哪类信息可靠`

## 6. Episode 怎么使用

玩家不看 Episode 菜单。

Episode 是后台包装：

```text
Episode
= Entry Conditions
+ World Changes
+ Quest Line
+ NPC State
+ Signals
+ Special Event Pool
+ Checkpoint
+ Unlock Bundle
```

玩家看见的是：
- 一条主线
- 一条短信
- 一个场地
- 一次测试
- 一件突然发生的事

### 首批 15 个 Episode 骨架

STAGE 1
1. 桌上先有一个东西开始运行
2. 第一个见证人
3. 第一次真正公开

STAGE 2
4. 两小时黑盒
5. 六小时搭建窗口
6. 凌晨后的故障恢复

STAGE 3
7. 第一个小委托
8. 一份 Open Call 和一页版本
9. 别人怎么描述你

STAGE 4
10. 失败文件不是垃圾
11. Remix 自己
12. 第一次把方法教给别人

STAGE 5
13. 28㎡ 临时基础设施
14. 从一个人到一套协作系统
15. 留下一份能重新打开的档案

## 7. 特殊事件分三类

### UNIVERSAL / 通用
只依赖基础状态，很多生涯都可能遇到：
- 开幕掉帧 12 秒
- 报价确认后又多一个需求
- `final_final_v7_REAL`
- 临时出现一个两小时空档
- 一张社交媒体帖子把作品解释歪了
- 旧硬盘突然读不出来
- “能不能再沉浸一点？”
- 一个看起来很破的转接头救了现场

### CONTEXTUAL / 条件事件
只有相关媒介 / 能力 / 项目存在才进池：
- 毫米波雷达误触发
- 多屏同步漂移
- 投影几何和观看距离冲突
- 旧格式无法解码
- 电力预算不足
- 作品尺寸过不了货梯
- 社群协作的同意与记录问题

### SIGNATURE / Episode 专属
只服务某条主线：
- 机构愿意邀请你，但不完全信任你
- 28㎡ 小空间突然可以接手
- 临时替补一场现场演出
- 失败项目被拆成下一件作品的材料

事件只能改变已有 Primitive：
- Project
- Evidence
- Asset / Blueprint
- Person memory
- Signal / Thread
- Cash / Attention / Time
- Archive

**不为事件临时发明新数值。**

## 9. “内容够不够”的判断标准

不再用“有多少卡 / 多少地点 / 多少 NPC”判断。

每个 Episode 必须至少包含：
- 1 个明确目标
- 1 个真实约束
- 1 个有记忆的人物互动
- 1 次 Route / Build / Commitment 决策
- 1 个可留下来的 Evidence
- 1 个后续会回来找你的后果
- 至少两种可行解法

每个特殊事件必须回答：
> 如果玩家选择不同，它三周以后到底哪里不同？

如果答案只是“+2 / -2”，就还不是值得保留的事件。
